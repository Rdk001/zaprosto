# Ручное создание записи администратором (05.6)

## Открытие

Войдите через /admin/login, откройте «Записи» и нажмите «Создать запись» либо перейдите на /admin/appointments/new. Страница, исходные данные и запросы свободного времени доступны только действующей административной сессии.

Новая миграция для 05.6 не добавлена: существующая схема полностью покрывает ручную запись. При обновлении установки достаточно собрать и запустить актуальный код штатным способом. prisma db push не использовать; рабочую БД и Docker volumes в рамках проверки не очищать.

## Создание

1. Выберите активную услугу.
2. Выберите конкретного активного назначенного мастера или «Любой мастер».
3. Выберите дату в текущем горизонте бизнеса. Все даты и часы показаны в указанной рядом именованной зоне.
4. Выберите актуальное свободное время.
5. Введите имя и российский телефон с префиксом +7 или 8. Пробелы, скобки и дефисы допустимы; сервер сохраняет +7XXXXXXXXXX.
6. Проверьте услугу, цену, длительность, исходный выбор мастера, дату, время и контакты.
7. Отметьте «Подтверждаю создание этой записи» и нажмите «Подтвердить создание».

Кнопка заблокирована без checkbox и во время запроса. Двойной клик и повтор исходной Action не создают вторую запись.

При выборе «Любой мастер» итоговый мастер назначается сервером существующим детерминированным алгоритмом. Карточка после успеха показывает фактически назначенного мастера, а запись сохраняет masterSelection=ANY.

## После успеха

Экран содержит сведения о записи, готовый plain-text и защищённую ссылку. Нажмите отдельно:

- «Копировать текст» — чтобы передать услугу, мастера, локальные дату/время, ссылку и предупреждение;
- «Копировать ссылку» — если нужен только доступ клиента;
- «Открыть карточку записи» — для журнала и последующего управления статусом.

Ссылка имеет вид https://текущий-origin/appointment#TOKEN. Она позволяет увидеть и отменить запись, поэтому её нельзя передавать посторонним. Если Clipboard API запрещён, интерфейс фокусирует и полностью выделяет поле: используйте обычное системное копирование.

Автоматической отправки по телефону или в Telegram нет. Администратор передаёт текст и ссылку клиенту самостоятельно. TelegramLink и NotificationOutbox не создаются.

## Конфликты и изменившиеся условия

- Если слот уже занят, время сбрасывается, загружаются свежие окна, а имя и телефон сохраняются.
- Если изменилась цена, название или длительность услуги, запись не создаётся. Проверьте новые условия, заново выберите время и подтвердите.
- Если изменилась зона или горизонт, форма получает новые даты, сбрасывает время и требует повторного подтверждения.
- Если услуга/мастер отключены, назначение удалено или график больше не допускает интервал, вернитесь к выбору.
- Ошибка в контактах не отправляет запрос; исправьте подсвеченное поле.

Выбранное время всегда сбрасывается при смене услуги, мастера, даты, service terms или business context. Старое согласие автоматически не переносится на новые условия.

## Потерянный ответ

До первого запроса точная исходная попытка сохраняется только в sessionStorage текущей вкладки. Если ответ потерян, запись могла сохраниться:

1. Не очищайте storage, не закрывайте вкладку и не начинайте новую запись.
2. Нажмите «Повторить исходный запрос». Повтор использует тот же payload, idempotency key и cancellation token.
3. При уже выполненном COMMIT сервер вернёт исходную запись и защищённую ссылку; при отсутствии записи создаст ровно эту попытку.
4. Если повтор невозможен из-за доступа или конфликта, проверьте журнал и клиентскую fragment-ссылку. Новую попытку начинайте только после ручной сверки.

Контакты удаляются из sessionStorage через 30 минут. Секрет ссылки остаётся минимальным marker для проверки, а новая запись блокируется до явного подтверждения, что результат сверен. Повреждённое storage ведёт себя так же безопасно. localStorage и cookie для попытки не используются.

## Доступ и секреты

Отзыв/истечение сессии или отключение администратора отклоняют чтение и создание, включая проверку после ожидания блокировок. Ответ отказа не содержит контактов и raw-токена. Уже видимые сведения открытой вкладки удалённо не стираются.

В БД хранится только cancellationTokenHash. Raw-токен не должен попадать в логи, query string, pathname, серверный HTML или RSC-параметры. Абсолютный URL создаётся браузером из текущего origin, а не из forwarded-заголовков.

## Проверка установки

Используйте только случайные БД штатного runner:

```bash
rtk npm run format:check
rtk npm run lint
rtk npm run build
rtk npm run typecheck
rtk proxy node --env-file=.env.example scripts/test-postgres.mjs
rtk proxy node --env-file=.env.example scripts/test-postgres.mjs --e2e
rtk git diff --check
rtk docker compose config
```

Build и typecheck выполняются последовательно. Runner создаёт zaprosto_test_*, применяет миграции только к ней и удаляет её в finally. Рабочую БД, реальные аккаунты и volumes не использовать для тестов.
