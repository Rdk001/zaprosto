# Журнал записей и управление статусами (05.5)

## Открытие и обновление установки

Войдите существующим аккаунтом через /admin/login, затем откройте «Записи» или /admin/appointments. Новых ролей и аккаунтов этот этап не создаёт.

Для обновления установки оператор должен отдельно подготовить резервную копию, применить новую миграцию через npm run prisma:migrate:deploy, затем выполнить npm run build и запустить актуальную сборку. db push не использовать. Миграция 20260831220000_appointment_version добавляет версию и индекс, не переписывает визиты. В рамках разработки она проверяется только на случайных БД штатного runner; к рабочей БД автоматически не применяется.

## Поиск записи

По умолчанию выбран сегодняшний день в зоне бизнеса и «Все, кроме отменённых». Укажите дату, мастера и статус, нажмите «Показать записи». Доступны прошлые и будущие даты независимо от горизонта создания новых записей. «Отменена» показывает только отменённые; «Все статусы» включает их вместе с остальными.

День определяется началом визита в текущей зоне бизнеса. Смена зоны может изменить отображаемые дату и часы, но не UTC-моменты. DST-дни не считаются равными 24 часам. Если полночь выбранного дня не существует или неоднозначна, журнал показывает ошибку без автоматического сдвига.

На странице до 25 записей, порядок — начало и ID. Внизу есть предыдущая/следующая страница; номер допускает значения 1–9 999 999. Фильтры сохраняются при пагинации, открытии карточки и возврате. Новый фильтр сбрасывает страницу на первую. Список выбора мастера также разделён на страницы по 50; выбранный мастер остаётся доступен и вне текущей страницы. Неактивные мастера помечены, их история остаётся видна.

В списке показаны время, мастер, услуга, имя клиента и статус. Название, цена и длительность услуги — исторический снимок, а не её текущие значения в каталоге. Если записи на странице отсутствуют, показано явное пустое состояние; при необходимости вернитесь на предыдущую страницу или измените фильтр.

## Карточка

Откройте название услуги. Карточка показывает начало/окончание в зоне бизнеса, мастера, снимок услуги, имя/телефон клиента, источник создания, статус, сведения об отмене и историю. История показывает по 25 событий с переходом статусов, временем, ролью инициатора, ID администратора и сохранённой причиной. «Следующие события» и «Предыдущие события» позволяют просмотреть её полностью.

Открытие карточки ничего не сохраняет. Защищённой ссылки клиента здесь нет: из сохранённого hash нельзя восстановить исходный секрет. Кнопки создания и переноса не добавлены.

## Смена статуса

Выберите «Новый статус» и нажмите «Сохранить статус».

| Исходный статус  | Разрешено                             |
| ---------------- | ------------------------------------- |
| Запланирована    | Отменена, Выполнена, Клиент не пришёл |
| Выполнена        | Клиент не пришёл                      |
| Клиент не пришёл | Выполнена                             |
| Отменена         | Переходов нет                         |

Результат визита можно отметить с момента начала. Сервер проверяет своё актуальное время после ожидания блокировок; часы компьютера этого не разрешают. Завершённые визиты нельзя отменять или возвращать в запланированные. Только отмена освобождает сохранённый интервал.

Для отмены обязательно отметьте «Подтверждаю отмену записи». Причина необязательна, до 1000 символов. Отмена окончательная; запись не удаляется, её исходные данные и снимки остаются. Сохраняются время, инициатор и причина, а также событие истории.

**Автоматические уведомления ещё не реализованы. При административной отмене самостоятельно свяжитесь с клиентом.** Telegram и outbox в 05.5 не подключаются.

После успешного сохранения карточка полностью перечитывается: статус, сведения об отмене и история обновляются вместе. Фильтры журнала и страница истории сохраняются.

## Конфликт, отзыв доступа и потеря ответа

Если карточку изменил другой администратор, отменил клиент либо изменились настройки времени, старая форма получает конфликт. Возврат к прежним значениям (ABA) также обнаруживается. Причина остаётся в исходной вкладке; автоматического принятия новой версии нет.

При сообщении «Результат неизвестен» сервер мог успеть выполнить действие. Не повторяйте запрос: нажмите «Сверить карточку (новая вкладка)», проверьте статус, историю и время отмены. Сохранение в старой форме заблокировано. Если требуется другое разрешённое действие, выполняйте его осознанно из свежей карточки после сверки. Повтор исходного запроса не добавляет историю и не меняет время отмены.

Если сеанс истёк, отозван или аккаунт отключён, новые чтения/изменения отклоняются, в том числе после ожидания блокировки. Войдите заново в другой вкладке, если доступ разрешён. Уже показанные в открытой вкладке сведения удалённо не стираются.

Автосохранения и хранения причины в browser storage нет. Закрытие/обновление исходной вкладки теряет ввод. При ошибке поля исправьте его; при сообщении о будущем визите дождитесь начала и повторите осознанно. Фокус переводится к сообщению об ошибке.

## Проверки и пределы

Запускайте только штатный scripts/test-postgres.mjs: он создаёт случайную zaprosto_test_* БД, применяет миграции и удаляет только её. Для стандартного локального PostgreSQL без .env:

```bash
rtk npm run format:check
rtk npm run lint
rtk npm run build
rtk npm run typecheck
rtk proxy node --env-file=.env.example scripts/test-postgres.mjs
rtk proxy node --env-file=.env.example scripts/test-postgres.mjs --e2e
rtk git diff --check
```

Build включает Prisma generate, web и worker; typecheck запускается только после его завершения. Рабочую БД, реальные аккаунты и Docker volumes не очищать. Снимки E2E содержат только вымышленные контакты и остаются в игнорируемом test-results.

Решение о блокировках и версиях — [ADR-0010](decisions/0010-admin-appointment-statuses.md); фактические результаты и непроверенные аспекты — [progress.md](progress.md). Прежний npm audit с 3 high в цепочке Prisma остаётся открытым; audit fix и обновления зависимостей этим этапом не выполняются. Ручное создание, редактирование контактов/услуги, перенос, медиа, уведомления и deployment не входят в 05.5.
