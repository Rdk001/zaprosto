# Журнал, статусы, контакты и перенос записи (05.5, 05.7.1, 05.7.2)

## Открытие и обновление установки

Войдите существующим аккаунтом через /admin/login, затем откройте «Записи» или /admin/appointments. Новых ролей и аккаунтов этот этап не создаёт.

Для обновления установки оператор должен отдельно подготовить резервную копию, применить новую миграцию через npm run prisma:migrate:deploy, затем выполнить npm run build и запустить актуальную сборку. db push не использовать. Миграция 20260831220000_appointment_version добавляет версию и индекс, не переписывает визиты. В рамках разработки она проверяется только на случайных БД штатного runner; к рабочей БД автоматически не применяется.

05.7.1 не добавляет новой миграции: существующая Appointment.version и текущие поля контактов полностью покрывают исправление.

05.7.2 также не добавляет миграций: перенос атомарно обновляет существующую Appointment и её version, не создавая вторую запись или новую сущность истории.

## Поиск записи

По умолчанию выбран сегодняшний день в зоне бизнеса и «Все, кроме отменённых». Укажите дату, мастера и статус, нажмите «Показать записи». Доступны прошлые и будущие даты независимо от горизонта создания новых записей. «Отменена» показывает только отменённые; «Все статусы» включает их вместе с остальными.

День определяется началом визита в текущей зоне бизнеса. Смена зоны может изменить отображаемые дату и часы, но не UTC-моменты. DST-дни не считаются равными 24 часам. Если полночь выбранного дня не существует или неоднозначна, журнал показывает ошибку без автоматического сдвига.

На странице до 25 записей, порядок — начало и ID. Внизу есть предыдущая/следующая страница; номер допускает значения 1–9 999 999. Фильтры сохраняются при пагинации, открытии карточки и возврате. Новый фильтр сбрасывает страницу на первую. Список выбора мастера также разделён на страницы по 50; выбранный мастер остаётся доступен и вне текущей страницы. Неактивные мастера помечены, их история остаётся видна.

В списке показаны время, мастер, услуга, имя клиента и статус. Название, цена и длительность услуги — исторический снимок, а не её текущие значения в каталоге. Если записи на странице отсутствуют, показано явное пустое состояние; при необходимости вернитесь на предыдущую страницу или измените фильтр.

## Карточка

Откройте название услуги. Карточка показывает начало/окончание в зоне бизнеса, мастера, снимок услуги, имя/телефон клиента, источник создания, статус, сведения об отмене и историю. История показывает по 25 событий с переходом статусов, временем, ролью инициатора, ID администратора и сохранённой причиной. «Следующие события» и «Предыдущие события» позволяют просмотреть её полностью.

Открытие карточки ничего не сохраняет. Защищённой ссылки клиента здесь нет: из сохранённого hash нельзя восстановить исходный секрет. Новая ручная запись создаётся отдельной кнопкой из журнала; исходная ссылка показывается только на успешном экране создания и безопасном replay. Для SCHEDULED-записи в карточке доступен отдельный редактор параметров визита.

## Исправление имени и телефона (05.7.1)

В карточке SCHEDULED, COMPLETED и NO_SHOW доступны поля имени и телефона. Они заполнены актуальными данными. Пробелы по краям имени удаляются; телефон принимает российский префикс +7 или 8, пробелы, скобки и дефисы и перед отправкой показывает итоговый +7XXXXXXXXXX. Без реального нормализованного изменения кнопка недоступна.

Для CANCELLED формы нет: «Отменённая запись хранится как историческая и не редактируется».

Сохранение меняет имя и телефон атомарно и увеличивает Appointment.version ровно на 1. Статус, источник, услуга, мастер, дата/время, snapshots, защищённая ссылка, BookingRequest, данные отмены и история статусов не меняются. Новое событие AppointmentStatusHistory не создаётся. TelegramLink и NotificationOutbox не создаются; исправление контактов не отправляет уведомление.

После подтверждённого успеха карточка полностью перечитывается с новым CSP nonce и показывает подтверждение. Защищённая клиентская ссылка и replay исходной публичной или ручной попытки показывают актуальные контакты той же записи без новой записи и без изменения исходного idempotency fingerprint.

Если другая форма, смена статуса или клиентская отмена уже увеличили version, черновик остаётся в текущей вкладке, а новая version автоматически не подставляется. При неизвестном результате запрос также не повторяется: откройте карточку в новой вкладке, сверьте фактические контакты, затем явно нажмите «Перечитать текущую карточку перед новой попыткой». Это перечитывание намеренно удаляет старый черновик.

Контакты не сохраняются в localStorage/cookie и не попадают в URL. Закрытие, навигация или перечитывание вкладки теряет черновик.

## Изменение параметров визита и перенос (05.7.2)

Редактор «Параметры визита» доступен только для SCHEDULED-записи. COMPLETED и NO_SHOW показывают неизменяемые параметры завершённого визита, но сохраняют отдельный редактор контактов. CANCELLED остаётся единым историческим состоянием: ни перенос, ни исправление контактов для неё недоступны.

Условия услуги выбираются явно:

- **KEEP_CURRENT** сохраняет serviceId и все исторические snapshots названия, цены и длительности; availability и новый конец интервала рассчитываются именно по сохранённой длительности;
- **CATALOG** применяет выбранную актуальную активную услугу и её текущие название, цену и длительность. Даже при том же serviceId текущие условия каталога не смешиваются с историческими автоматически. Неактивную услугу нельзя выбрать заново.

Для каждого варианта выберите конкретного активного назначенного мастера (**SPECIFIC**) либо «Любой свободный мастер» (**ANY**), дату и предложенный интервал. Изменение услуги, мастера, даты или business context сбрасывает устаревший выбор времени. Запоздавший ответ availability игнорируется. Перед сохранением интерфейс показывает «Было / Станет» и требует отдельный checkbox подтверждения.

Сервер повторно проверяет активную административную сессию, актуальные Appointment.version/status, business context, service terms, назначения и расписание после ожидания блокировок. Существующая Appointment блокируется через SELECT ... FOR UPDATE; старый интервал освобождается и новый занимается одним UPDATE в той же транзакции. PostgreSQL exclusion constraint остаётся окончательной защитой от пересечения. Успех увеличивает version ровно на 1, не создаёт Appointment, BookingRequest или AppointmentStatusHistory и не меняет контакты, источник, данные отмены, cancellation token/hash, TelegramLink или NotificationOutbox.

После подтверждённого успеха выполняется полная навигация с безопасным `visitUpdated=1`, свежим серверным чтением и новым CSP nonce. Безопасные фильтры журнала, page и historyPage сохраняются. Черновик переноса, version, service/master/date/time, контакты, tokens и hashes не помещаются в URL, cookies или browser storage.

Если interval уже занят, время сбрасывается, а выбранные услуга, мастер и дата остаются вместе со свежим списком availability. При CONFLICT, изменении каталога/business context, потере доступа или неизвестном результате старое намерение автоматически не повторяется и новая version не подставляется. Черновик остаётся только в памяти вкладки; сначала откройте свежую карточку в новой вкладке либо полностью перечитайте текущую, сверьте фактическое состояние и лишь затем сформируйте новое намерение.

**Автоматическое уведомление о переносе в 05.7.2 не отправляется. Администратор должен самостоятельно связаться с клиентом.** Telegram/outbox остаются этапом 06.

## Смена статуса

Выберите «Новый статус» и нажмите «Сохранить статус».

| Исходный статус  | Разрешено                             |
| ---------------- | ------------------------------------- |
| Запланирована    | Отменена, Выполнена, Клиент не пришёл |
| Выполнена        | Клиент не пришёл                      |
| Клиент не пришёл | Выполнена                             |
| Отменена         | Переходов нет                         |

Результат визита можно отметить с момента начала. Сервер проверяет своё актуальное время после ожидания блокировок; часы компьютера этого не разрешают. Завершённые визиты нельзя отменять или возвращать в запланированные. Только отмена освобождает сохранённый интервал.

Для отмены обязательно отметьте «Подтверждаю отмену записи». Причина необязательна, до 1000 символов. Отмена окончательная; запись не удаляется, её исходные данные и снимки остаются. Сохраняются время, инициатор и причина, а также событие истории.

**Автоматические уведомления ещё не реализованы. При административной отмене самостоятельно свяжитесь с клиентом.** Telegram и outbox в 05.5 не подключаются.

После успешного сохранения карточка полностью перечитывается: статус, сведения об отмене и история обновляются вместе. Фильтры журнала и страница истории сохраняются.

## Конфликт, отзыв доступа и потеря ответа

Если карточку изменил другой администратор, отменил клиент либо изменились настройки времени, старая форма получает конфликт. Возврат к прежним значениям (ABA) также обнаруживается. Причина отмены, черновик контактов или черновик переноса остаются в исходной вкладке; автоматического принятия новой версии нет.

При сообщении «Результат неизвестен» сервер мог успеть выполнить действие. Не повторяйте запрос: нажмите «Сверить карточку (новая вкладка)», проверьте статус, историю и время отмены. Сохранение в старой форме заблокировано. Если требуется другое разрешённое действие, выполняйте его осознанно из свежей карточки после сверки. Повтор исходного запроса не добавляет историю и не меняет время отмены.

Если сеанс истёк, отозван или аккаунт отключён, новые чтения/изменения отклоняются, в том числе после ожидания блокировки. Войдите заново в другой вкладке, если доступ разрешён. Уже показанные в открытой вкладке сведения удалённо не стираются.

Автосохранения и хранения причины в browser storage нет. Закрытие/обновление исходной вкладки теряет ввод. При ошибке поля исправьте его; при сообщении о будущем визите дождитесь начала и повторите осознанно. Фокус переводится к сообщению об ошибке.

## Проверки и пределы

Запускайте только штатный scripts/test-postgres.mjs: он создаёт случайную zaprosto_test_* БД, применяет миграции и удаляет только её. Для стандартного локального PostgreSQL без .env:

```bash
rtk npm run format:check
rtk npm run lint
rtk npm run build
rtk npm run typecheck
rtk proxy node --env-file=.env.example scripts/test-postgres.mjs
rtk proxy node --env-file=.env.example scripts/test-postgres.mjs --e2e
rtk git diff --check
```

Build включает Prisma generate, web и worker; typecheck запускается только после его завершения. Рабочую БД, реальные аккаунты и Docker volumes не очищать. Снимки E2E содержат только вымышленные контакты и остаются в игнорируемом test-results.

Решение о статусах — [ADR-0010](decisions/0010-admin-appointment-statuses.md), о контактном исправлении — Accepted [ADR-0012](decisions/0012-admin-appointment-contact-correction.md), о переносе — Proposed [ADR-0013](decisions/0013-admin-appointment-rescheduling.md); фактические результаты и непроверенные аспекты — [progress.md](progress.md). Прежний npm audit с 3 high в цепочке Prisma остаётся открытым; audit fix и обновления зависимостей этим этапом не выполняются. Ручное создание реализовано отдельным этапом 05.6 и описано в [собственной инструкции](admin-appointment-creation.md). Медиа, автоматические уведомления и deployment не реализованы.
