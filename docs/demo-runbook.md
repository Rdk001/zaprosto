# Демонстрация release-кандидата MVP

Этот runbook предназначен для локального показа одной отдельной установки
«Запросто»: один бизнес, один филиал, одна PostgreSQL. Используйте только
вымышленные имена и телефоны. Реальные Telegram credentials, внешняя Telegram-сеть,
production deploy и платные сервисы для локальной демонстрации не нужны.

Короткая повторяемая приёмка вынесена в
[demo-acceptance-checklist.md](demo-acceptance-checklist.md). Mobile-матрица — в
[demo-mobile-checklist.md](demo-mobile-checklist.md), production-развёртывание — в
[deployment.md](deployment.md), передача заказчику — в
[customer-handoff.md](customer-handoff.md).

## Требования и безопасная граница

- Node.js 24, npm 11, Docker Engine/Desktop с Compose и Chromium для Playwright;
- чистый проверенный checkout, свободные порты 3000, 3108 и 5432;
- локальный PostgreSQL 17 из `docker-compose.yml` либо эквивалентный тестовый сервер;
- пользователь PostgreSQL с правом `CREATE DATABASE` для isolated runners;
- отдельное точное имя demo-БД вида `zaprosto_demo_073_YYYYMMDDHHMMSS`.

Не используйте рабочую БД и не запускайте `prisma db push`, `migrate reset`,
`docker compose down --volumes` или очистку таблиц. Зафиксируйте точное имя созданной
demo-БД: после показа удаляется только она. Не включайте запись терминала, HAR,
browser trace или session replay при вводе admin-пароля и работе с защищёнными
ссылками.

## Чистый локальный запуск

Команды ниже приведены для PowerShell. Сначала установите зафиксированные
зависимости и поднимите только PostgreSQL:

```powershell
npm ci
if (Test-Path .env) { throw ".env уже существует; проверьте его вручную и не перезаписывайте" }
Copy-Item .env.example .env
docker compose up -d --wait db
```

Выберите новое точное имя, убедитесь, что оно соответствует указанному префиксу, и
создайте только эту БД. Пример имени нужно заменить на уникальное для текущего
показа:

```powershell
$DemoDb = "zaprosto_demo_073_20260920180000"
if ($DemoDb -notmatch '^zaprosto_demo_073_[0-9]{14}$') { throw "Неверное имя demo-БД" }
docker compose exec -T db createdb -U zaprosto $DemoDb
$env:DATABASE_URL = "postgresql://zaprosto:zaprosto_local_only@localhost:5432/$($DemoDb)?schema=public"
$env:PUBLIC_ORIGIN = "http://localhost:3000"
```

Не сохраняйте эти значения в tracked-файлах. Примените миграции, проверьте их
состояние и явно добавьте безопасный каталог:

```powershell
npm run prisma:generate
npm run prisma:migrate:deploy
npm run prisma:migrate:status
npm run demo:seed
npm run demo:seed
```

Второй `demo:seed` обязателен для репетиции идемпотентности. Команда добавляет только
три услуги, двух мастеров, недельные часы и перерывы с зарезервированными UUID. Она
не очищает и не перезаписывает существующие строки, не создаёт записи, контакты,
администратора или Telegram-связи. Поэтому запускайте её только в отдельной
demo-БД, даже несмотря на безопасное поведение.

Создайте первого администратора интерактивно:

```powershell
npm run admin:create
```

Логин и пароль вводятся только в TTY; пароль скрыт и не передаётся через argv,
pipe, `.env`, чат или запись экрана. Для повторной репетиции используйте новую
demo-БД: `admin:create` намеренно не перезаписывает существующего администратора.

Для показа production-поведения сначала соберите приложение, затем запустите web:

```powershell
npm run build
npm run start
```

Откройте `http://localhost:3000`. Не запускайте одновременно `npm run dev` и
`npm run start`. Если нужна быстрая разработческая репетиция вместо production
режима, используйте `npm run dev` с теми же `DATABASE_URL` и `PUBLIC_ORIGIN`.

## Telegram без реальной сети

Для основного локального показа worker не нужен. Оставьте
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME` unset: Telegram штатно выключен, а
web и основная запись работают независимо. При необходимости покажите disabled
worker в отдельном терминале командой `npm run worker`; ожидается безопасный код
готовности без Bot API call, после чего завершите процесс `Ctrl+C`.

Fake/local подключение клиента и администратора демонстрируется существующими
Chromium E2E `booking.spec.ts` и `admin.spec.ts`. Они используют локальный fake
transport и отдельную `zaprosto_test_*` БД. Не подставляйте фиктивный token в
production adapter и не вызывайте `api.telegram.org` через curl. Защищённый health и
правила production-диагностики описаны в
[telegram-observability-runbook.md](telegram-observability-runbook.md).

## Порядок показа

1. **Клиент, конкретный мастер.** На `/` выберите услугу, мастера, дату и окно;
   введите, например, `Вымышленный Клиент` и `8 (999) 000-00-00`. Покажите
   нормализацию телефона, итоговые цену/длительность и подтверждение.
2. **Защищённая ссылка.** Скопируйте fragment-ссылку только в отдельный
   демонстрационный профиль браузера. Покажите карточку и явное подтверждение
   отмены. Не вставляйте ссылку в логи, чат, query string или pathname.
3. **«Любой мастер».** Создайте вторую вымышленную запись и покажите фактически
   назначенного мастера. Подчеркните повторную проверку окна и отсутствие
   клиентского самостоятельного переноса.
4. **Администратор.** Войдите через `/admin/login`; покажите обзор, выход и возврат
   защищённой страницы к форме входа.
5. **Каталог и расписание.** Покажите услуги, мастеров, назначения и порядок;
   недельные часы, перерыв, выходной/особые часы; затем горизонт 7–90 дней и
   именованный часовой пояс.
6. **Журнал и ручная запись.** Откройте фильтры и карточку, создайте телефонную
   запись с вымышленными контактами, скопируйте готовый текст и fragment-ссылку.
   Автоматической отправки по одному телефону нет.
7. **Контакты и перенос.** Исправьте имя/телефон отдельным действием; затем для
   запланированного визита покажите `KEEP_CURRENT` или `CATALOG`,
   `SPECIFIC`/`ANY`, сравнение «Было / Станет» и явное подтверждение.
8. **Статусы.** Покажите отмену и историю. `Выполнена`/`Клиент не пришёл`
   разрешены только после начала визита; не переводите будущий визит обходным SQL.
   Если начавшейся вымышленной записи нет, воспроизведите статусный сценарий через
   `admin-appointments.spec.ts` в isolated E2E-БД.
9. **Telegram.** Покажите только disabled health/worker либо fake/local E2E:
   добровольное подключение/отключение, без реального бота и сети.

На мобильном экране используйте 390×844, для desktop — 1440×900. Полная принятая
матрица 360×800, 390×844, 412×915 и 1440×900 уже встроена в существующие specs;
детали ручной проверки находятся в mobile checklist.

## Безопасные сбои и восстановление

- **Порт занят:** остановите только известный процесс этой репетиции либо выберите
  другой порт и задайте точно совпадающий `PUBLIC_ORIGIN`.
- **Миграция не прошла:** web не запускайте. Проверьте точный `DATABASE_URL`,
  доступность отдельной demo-БД и повторите `migrate deploy`; не используйте reset.
- **Нет свободных окон:** проверьте активность, назначение услуги, недельные часы,
  перерывы, исключения, горизонт и зону. Seed создаёт часы 10:00–20:00 и перерыв
  14:00–15:00 на каждый день.
- **Конфликт/изменившиеся условия:** перечитайте актуальную форму, заново выберите
  окно и подтвердите. Не повторяйте старое намерение автоматически.
- **Результат сохранения неизвестен:** не создавайте вторую попытку. Сохраните
  вкладку, откройте журнал/карточку или повторите именно исходную idempotent-пару.
- **Admin-доступ потерян:** в demo-БД выполните интерактивный
  `npm run admin:reset`; не правьте password hash вручную.
- **Telegram NOT_READY:** ожидаемо при unset credentials. Не добавляйте token ради
  устранения этого состояния.

## Завершение и очистка

1. Остановите web и необязательный worker через `Ctrl+C`. Убедитесь, что порт 3000
   освобождён; E2E runner сам освобождает 3108.
2. Повторно выведите `$DemoDb`, проверьте regex и точное имя. Это должна быть БД
   текущего показа, а не `zaprosto`, `postgres` или чужая база.
3. Удалите только её:

   ```powershell
   if ($DemoDb -notmatch '^zaprosto_demo_073_[0-9]{14}$') { throw "Отказ от удаления" }
   docker compose exec -T db dropdb -U zaprosto --force $DemoDb
   ```

4. Обычный `docker compose stop db` допустим, если контейнер был запущен для этой
   репетиции. Не используйте `down --volumes`.
5. Удалите локальный `.env` только если он создан специально для репетиции и не
   содержит нужных пользователю настроек. Не удаляйте его автоматически.

В production demo seed не используется. Внешний deploy, VPS/domain, реальные bot и
token выполняются только отдельной процедурой заказчика; VPS, домен и резервное
хранилище оплачивает заказчик.
