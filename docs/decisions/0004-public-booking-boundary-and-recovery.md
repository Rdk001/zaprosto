# ADR-0004: Публичные границы, ссылка без секрета в URL запроса и восстановление попытки

- Статус: Accepted
- Дата: 2026-08-30

## Контекст

04.2 подключает готовые сервисы к браузеру. Нужны безопасный повтор при потере ответа, отмена только по явному действию и ограничение частоты между несколькими процессами без платного сервиса.

## Решение

- Каталог читает Server Component через серверный модуль. Создание, подготовка секрета и отмена идут через Server Actions и существующие сервисы. Единственный новый GET Route Handler — доступность: он позволяет отменять параллельные запросы браузера и отбрасывать устаревшие ответы без очереди Server Actions.
- Защищённая ссылка имеет вид `/appointment#<token>`. Fragment не передаётся HTTP-серверу, поэтому GET, prefetch и preview не содержат секрет и не изменяют запись. Клиент передаёт секрет в POST-теле действия чтения, вызывающего ClientAppointmentService. В URL запроса, серверных props и публичном каталоге токена нет. Действие чтения ничего не отменяет.
- Все Actions проверяют точное совпадение Origin с обязательным PUBLIC_ORIGIN и отклоняют неподходящий Sec-Fetch-Site. Host и forwarded-заголовки не являются источником разрешённого origin. Встроенная защита Next.js остаётся включённой.
- Счётчики public_rate_limits живут в PostgreSQL, используют время БД и атомарный UPSERT. Есть отдельные минутные пределы для клиента и всей установки. Проверки работают для нескольких процессов. При сбое limiter операция закрывается безопасным ответом UNAVAILABLE.
- По умолчанию все посетители используют общий client bucket. Индивидуальные IP-лимиты включаются только через явно настроенный доверенный proxy: он заменяет X-Zaprosto-Client-IP и запрещает прямой доступ к приложению. Произвольные X-Forwarded-For и X-Real-IP игнорируются; глобальный лимит остаётся при любой конфигурации. IP нормализуется и хранится как SHA-256, открытый IP в таблицу не записывается.
- Перед первым create клиент сохраняет и перечитывает исходные данные вместе с парой из prepareBookingAttempt. sessionStorage привязан к вкладке, переживает reload и не превращает неизвестный сетевой результат в новый запрос. Повтор использует исходные данные и ту же пару. Блокировка обработчика предотвращает двойной клик.
- Контакты для повтора имеют TTL 30 минут. После него сохраняется только секрет проверки и маркер неопределённого результата; автоматического нового бронирования нет. Повреждённое состояние тоже блокирует новый запрос. При успехе контакты заменяются компактным маркером ссылки, при подтверждённом отказе удаляются; форма сохраняет контакты только в памяти.
- CSP с новым nonce на каждый документ, no-store, no-referrer, noindex, запрет iframe и отсутствие сторонней аналитики защищают персональные страницы. Секреты и ошибки Prisma не журналируются и не возвращаются клиенту.

## Последствия

Добавлена одна версионированная таблица счётчиков, без новых зависимостей и без сброса БД. Политика лимитов — технический предел, не изменение бизнес-правил бронирования.

Fragment-ссылка требует JavaScript для просмотра. Секрет доступен JavaScript того же origin, поэтому XSS остаётся критическим риском. CSP не заменяет экранирование и запрет сторонних скриптов.

Закрытие вкладки обычно удаляет sessionStorage, однако браузер может восстановить вкладку. Клиент должен сохранить защищённую ссылку. Срок действия самой ссылки не ограничивается. После удаления контактов невозможно повторить исходный create автоматически; доступна проверка ссылки. Если исходный результат не установлен, новая попытка требует осознанного действия и может создать вторую запись.

Счётчики ограничивают прикладные операции, но не заменяют сетевую защиту от DDoS. Общий fallback может ограничить всех посетителей сразу. Конфигурация и очистка описаны в [public-booking.md](../public-booking.md).
