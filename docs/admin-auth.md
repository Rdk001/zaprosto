# Вход администратора: настройка и эксплуатация (05.1)

## Первоначальная настройка

Требуются Node.js 24, зависимости из package-lock и применённые миграции. В доверенном локальном checkout оператора задайте DATABASE_URL в защищённом окружении либо в локальном .env (не коммитить). PUBLIC_ORIGIN должен точно совпадать с origin браузера, без завершающего slash.

```bash
npm ci
npm run prisma:generate
npm run prisma:migrate:deploy
npm run admin:create
```

CLI спрашивает логин и дважды пароль в интерактивном TTY. Ввод пароля полностью скрыт; не передавайте его через аргумент, pipe, shell history или чат. Логин: 3–64 латинских символа/цифры и ._-, без пробелов, регистр не учитывается. Пароль: 12–128 символов, не обрезается; используйте уникальную длинную фразу. Ctrl+C отменяет ввод и восстанавливает режим терминала. Из JS-строк нельзя гарантированно стереть все копии секрета из памяти, поэтому работайте только на доверенном компьютере без записи терминальной сессии.

Команда создаёт только первого администратора. Если в БД уже есть любой AdminUser, повторный запуск завершается ошибкой без изменения пароля, активности и сессий. При параллельных вызовах создаётся только одна учётная запись. Никакой администратор не создаётся при build, запуске, миграциях или demo:seed. Реальные учётные данные должен вводить оператор самостоятельно.

Откройте `/admin/login`, введите созданные данные: после входа `/admin` показывает логин и кнопку «Выйти». В 05.2 добавлены защищённые разделы услуг и мастеров; см. [управление каталогом](admin-catalog.md). В 05.3 добавлено [управление расписанием](admin-schedule.md). Управление записями ещё не реализовано. После выхода повторный переход на /admin требует входа.

## Локальный HTTP и production HTTPS

- Локально: PUBLIC_ORIGIN=http://localhost:3000 (или точный loopback origin с другим портом). Cookie `zaprosto-admin-local`, HttpOnly, SameSite=Lax, Path=/, без Secure. Это применимо и к локальному next start или Docker NODE_ENV=production.
- Для пользователей: PUBLIC_ORIGIN=https://ваш-домен. Cookie `__Host-zaprosto-admin`, HttpOnly, Secure, SameSite=Lax, Path=/, без Domain. Приложение запрещает административную аутентификацию с не-loopback HTTP-origin.
- HTTPS завершается на доверенном reverse proxy. Он должен сохранять публичный Host либо корректно заменять X-Forwarded-Host для встроенной проверки Next.js; приложение само сравнивает Origin с PUBLIC_ORIGIN. Не включайте wildcard allowedOrigins.
- Закройте прямой доступ к приложению извне proxy. TRUST_PROXY_CLIENT_IP=false по умолчанию; включайте true только если proxy **перезаписывает** X-Zaprosto-Client-IP, а клиенты не могут обратиться в обход него. Произвольные X-Forwarded-For/X-Real-IP игнорируются. См. также [публичную защиту](public-booking.md).
- Cookie policy определяется конфигурацией origin, не X-Forwarded-Proto и не клиентским IP-заголовком. При смене HTTP на HTTPS сначала отзовите тестовые сессии и очистите локальную cookie; не используйте реальные пароли в открытом HTTP.
- Не сохраняйте тела запросов, Cookie/Set-Cookie и Authorization в proxy/APM/debug-логах. Не включайте запись браузерных traces для реальных входов. Не кешируйте /admin и ответы Server Actions в CDN/proxy.

## Восстановление доступа оператором

Публичного сброса, email/SMS и OAuth нет. Оператор с доверенным доступом к нужной БД запускает:

```bash
npm run admin:reset
```

Введите существующий логин и дважды новый пароль скрытым вводом. Команда явно предупреждает об отзыве сессий. Изменение hash, сброс временной блокировки и отзыв всех сессий атомарны. Старый пароль и прежние токены после успешного сброса не дают доступа. Неизвестный логин не создаёт пользователя. Деактивированный аккаунт остаётся деактивированным: его восстановление требует отдельного осознанного решения оператора, сброс пароля не является командой активации.

На сервере используйте доверенный checkout той же версии с Node.js 24 и `npm ci`; передавайте DATABASE_URL через защищённое окружение, например внутри SSH-сеанса оператора. Не открывайте PostgreSQL всему интернету. Минимальный Docker runner содержит web/worker, но не tsx, Prisma CLI и исходный операторский скрипт; команды настройки запускаются из release-checkout, а не через `docker compose exec web npm run admin:create`.

До аварийных SQL-изменений сделайте резервную копию. Для экстренного отзыва доступа оператор может деактивировать нужного AdminUser и отозвать его AdminSession средствами PostgreSQL в транзакции, сверив конкретный логин; не копируйте password_hash вручную и не задавайте всем один пароль. Следующий запрос к закрытым данным увидит деактивацию.

## Лимиты и сессии

- 10 валидных попыток входа/минуту на клиента, 60 на установку, включая успешные; без доверенного proxy клиентский bucket общий.
- 5 неправильных паролей → 15 минут блокировки. Попытки во время блокировки срок не продлевают. По истечении можно повторить вход.
- Сессия действует 12 часов, не продлевается автоматически. Выход отзывает текущую, операторский reset — все сессии администратора.
- При недоступной БД закрытые данные не выдаются. Если выход не подтверждён, восстановите связь и повторите его; очистка браузерной cookie сама по себе не отзывает серверный токен.
- Истёкшие rate-limit строки чистятся существующим limiter. Для небольшого MVP отдельная очистка сессий не запускается автоматически; при накоплении оператор может удалить только истёкшие или отозванные строки, не затрагивая активные.

## Проверки разработки

Рабочая БД не очищается. Для стандартного локального Compose без .env:

```bash
docker compose up -d --wait db
npm run build
npm run typecheck
npm run format:check
npm run lint
node --env-file=.env.example scripts/test-postgres.mjs
node --env-file=.env.example scripts/test-postgres.mjs --e2e
docker build -t zaprosto-auth-check:local .
```

С собственным защищённым .env используйте `npm run test:postgres` и `npm run test:e2e`. Runner создаёт случайную zaprosto_test_* БД, применяет миграции, удаляет только созданную им БД. Существующие базы и volumes не сбрасываются. Build/Prisma generate должны завершиться **до** typecheck. E2E используют порт 3108, production-сборку, вымышленные аккаунты в тестовой БД, traces выключены; снимки входа делаются до ввода пароля.

Решения, параметры и ограничения безопасности — [ADR-0005](decisions/0005-admin-authentication-and-sessions.md).
