# Настройка расписания мастера (05.3)

## Открытие

Войдите существующим аккаунтом через `/admin/login`. Откройте «Расписание» в навигации или ссылку «Расписание» в карточке `/admin/masters`. Выберите мастера и нажмите «Открыть график». Список показывает до 50 мастеров; ссылка «Следующие мастера» открывает следующую страницу. Неактивные мастера явно помечены и доступны для настройки. Сохранение графика не активирует мастера и не назначает услуги.

Часовой пояс берётся из `BusinessSettings.timezone` и показан над редактором. Даты и часы относятся к бизнесу, даже если компьютер или браузер находится в другой зоне. Изменение зоны и горизонта реализовано отдельно в [настройках 05.4](admin-settings.md). Новому мастеру график автоматически не создаётся.

## Недельные часы и перерывы

Для каждого дня с понедельника по воскресенье добавьте рабочие интервалы и перерывы. Кнопки добавления и удаления работают с клавиатуры; после добавления фокус переходит в начало новой строки, после удаления — на кнопку добавления. Пустая работа означает отсутствие регулярных рабочих часов. Нажмите «Сохранить неделю»: все семь дней и перерывы сохраняются одной операцией.

Время: строго `HH:mm`, например `09:07–12:22`. Минуты не обязаны быть кратными 15. Допустимы `00:00–23:59`; начало строго раньше конца. `24:00`, секунды, одинаковые и обратные границы отклоняются. Ночных смен и автоматического переноса на следующую дату нет. Соседние, пересекающиеся и повторяющиеся интервалы сервер объединяет, сохраняя их суммарное покрытие. Сохранённый нормализованный результат появляется в форме.

Перерывы вне текущей работы не удаляются: они могут понадобиться при особых часах. Доступность вычитает только пересечение перерыва с работой. Технический предел — 16 исходных рабочих интервалов и 16 перерывов на каждый день (224 на запрос). Такой запрос укладывается в существующий лимит Server Actions 16 КиБ. Это предел редактора, не правило о длительности визита.

## Исключения на конкретные даты

Список ограничен выбранным календарным месяцем (до 31 даты). Можно выбрать другой месяц; создаваемая дата не ограничена этим месяцем. Если исключение сохраняется на другую дату вне выбранного месяца, откройте соответствующий месяц для просмотра.

- **Выходной / DAY_OFF** полностью закрывает день, независимо от недельных часов и перерывов.
- **Особые часы / CUSTOM_HOURS** заменяют только недельные рабочие интервалы. Недельные перерывы продолжают действовать. Требуется хотя бы один рабочий интервал, максимум 16.
- Без исключения действуют недельные часы и перерывы.

Нажмите «Добавить исключение», укажите дату, тип и при необходимости часы, затем «Сохранить исключение». «Изменить» позволяет изменить дату, тип и интервалы. На дату мастера может быть только одно исключение: занятая дата вызывает конфликт, а не замену чужого изменения. Переключение типа очищает интервалы в черновике; при сохранении DAY_OFF особых часов в БД не остаётся. Замена типа и интервалов атомарна.

«Удалить» сначала открывает объяснение и флажок подтверждения возврата к недельному графику. До подтверждения удаления не происходит. Удаление исключения и его часов выполняется одной транзакцией.

Для датированных часов сервер проверяет каждую исходную границу в конкретной дате и зоне **до** объединения интервалов, а также действующие недельные перерывы. Несуществующее или неоднозначное DST-время отклоняется с указанием даты, времени и зоны. Смещения и округления нет. DAY_OFF не конвертирует неиспользуемые часы и перерывы. У недельного графика нет конкретной даты: на переходах DST действует строгая проверка существующего scheduling; для проблемного дня задайте корректные особые часы либо выходной. Неоднозначные начала публичных окон исключаются прежним алгоритмом, точная длительность сохраняется.

## Записи, конкуренция и потеря связи

Изменения графика **не отменяют, не переносят и не переписывают** существующие записи, снимки услуги, историю и защищённые ссылки. Новые запросы доступности сразу читают текущий график без перезапуска. Старая публичная форма повторно проверяется при создании и не может забронировать уже закрытое время. Успешный replay прежнего запроса возвращает ту же запись даже после закрытия её дня. Согласование условий услуги не меняется.

С 05.4 редактор также предъявляет исходный контекст BusinessSettings. После изменения настроек (включая возврат к прежним значениям) старая форма не сохраняет часы молча в новой зоне: получает конфликт и сохраняет ввод для сверки. Контекст не обновляется автоматически; откройте свежую форму отдельно. См. [ADR-0009](decisions/0009-business-time-context.md).

Недельный график, все исключения, карточка и порядок конкретного мастера используют общий `Master.version`. При изменении любого из них старая форма может получить конфликт. Сохранение блокируется, введённые значения остаются в исходной вкладке. Откройте «Проверить актуальное расписание (новая вкладка)», сравните график, карточку и порядок, затем осознанно внесите нужное в свежую форму. Автоматического объединения чужих изменений нет.

Если показано «Сохранение не подтверждено», сервер мог успеть сохранить запрос. Автоматический повтор запрещён; сначала сверьте актуальные данные в новой вкладке. Это относится также к удалению. При завершении сеанса войдите в другой вкладке и проверьте состояние; черновик исходной вкладки сохраняется. Черновики не сохраняются в browser storage. Закрытие редактора, переход между мастерами, месяцами или страницами теряет несохранённый ввод; интерфейс предупреждает об этом.

Каждое чтение и каждая Action проверяют активный аккаунт и сессию непосредственно у данных; после ожидания замка проверка повторяется. GET ничего не изменяет. Origin/CSRF, nonce-CSP, no-store и полная навигация сохранены. Контакты клиентов не читаются редактором.

## Разработка и пределы

Новых зависимостей, таблиц и миграций 05.3 нет: используются существующие модели расписания и версия мастера из миграции 05.2. Не используйте `db push`. Прямой SQL в обход протокола версий не защищает открытые формы; оператор должен отдельно согласовать такие изменения. Данные старого графика с секундами, `24:00` или превышением лимита не обрезаются: редактор отказывает в чтении, требуется проверка оператором.

Проверки выполняются только на случайной `zaprosto_test_*` БД через существующий runner:

```bash
npm run format:check
npm run lint
npm run build
npm run typecheck
node --env-file=.env.example scripts/test-postgres.mjs
node --env-file=.env.example scripts/test-postgres.mjs --e2e
git diff --check
```

Build/Prisma generate и typecheck выполняйте последовательно. Для собственной конфигурации используйте `npm run test:postgres` / `npm run test:e2e`. Рабочие БД, аккаунты и Docker volumes не очищаются. Решения — [ADR-0008](decisions/0008-admin-schedule-concurrency.md), фактические результаты и ограничения — [progress.md](progress.md). Вопрос npm audit из 05.1 остаётся открытым; обновления зависимостей не входят в 05.3.
