# Запросто

**Запросто (Zaprosto)** — русскоязычная система онлайн-записи для барбершопа. Проект создаётся как практичный портфолио-продукт, который впоследствии можно адаптировать и предлагать российскому малому бизнесу, в том числе через Kwork.

Главная цель первой версии — надёжно решить основной сценарий записи без преждевременного усложнения архитектуры и без платных сервисов.

## Возможности целевого MVP

Клиент выбирает услугу, назначенного ей мастера или «Любого мастера», дату и доступное время, указывает обязательные имя и российский телефон и получает подтверждение записи. Telegram подключается добровольно; email не собирается. Администратор назначает услуги мастерам и управляет мастерами, графиками, перерывами, выходными и записями.

Свободные окна рассчитываются по длительности выбранной услуги, графику мастера, перерывам, выходным и существующим записям. Пересечения записей запрещены. Клиент может отменить запись по защищённой ссылке; для переноса он отменяет старую запись и создаёт новую. Администратор может отменять и переносить записи.

Телефон принимается с префиксом `+7` или `8`, допускает пробелы, скобки и дефисы и сохраняется в формате `+7XXXXXXXXXX`. Администратор может вручную создавать и редактировать записи и отмечать визит как выполненный или несостоявшийся из-за неявки клиента. Ручная запись сразу блокирует слот, а готовый текст подтверждения и защищённую ссылку администратор отправляет клиенту самостоятельно.

Записи не удаляются при отмене: слот освобождается, а запись и данные отмены остаются в истории. Клиент с подключённым Telegram получает уведомления при значимых административных изменениях; без Telegram администратор связывается с ним по телефону.

Горизонт бронирования настраивается от 7 до 90 дней и по умолчанию равен 30 дням. Часовой пояс бизнеса также настраивается, по умолчанию используется `Europe/Moscow`; моменты времени хранятся в UTC.

## Ограничения

- Интерфейс mobile-first и полностью русскоязычный.
- На старте используются только бесплатные тарифы и бесплатные сервисы.
- Клиент выбирает готовую услугу, а не произвольную длительность визита.
- Одна установка обслуживает один барбершоп и один филиал; для каждого покупателя разворачивается отдельный экземпляр.
- Мультифилиальность и многопользовательский SaaS не входят в MVP.
- Утверждён модульный Next.js-монолит с PostgreSQL и отдельным экземпляром для каждого барбершопа.

## Текущее состояние

Выполнены этапы 00–03, серверная часть 04.1 и клиентский интерфейс 04.2. Помимо каркаса Next.js-монолита, Prisma-модели, миграций и локальной Docker Compose-инфраструктуры реализован серверный модуль `scheduling`. Его чистая предметная часть рассчитывает полуоткрытые доступные интервалы, а прикладной сервис учитывает назначения услуг, графики, перерывы, исключения, существующие записи и горизонт бронирования. Сетка начал с шагом 15 минут строится в локальном календарном времени бизнеса: несуществующие и неоднозначные начала при DST не предлагаются, не сдвигаются и не дублируются, а некорректная граница действующего рабочего интервала или перерыва завершает расчёт типизированной ошибкой. Исключения применяются до преобразования в UTC: `DAY_OFF` исключает недельные часы и перерывы, сохраняя дневную загрузку, а `CUSTOM_HOURS` заменяет недельные часы, но сохраняет недельные перерывы. Алгоритм «Любой мастер» объединяет окна, сохраняет свободных кандидатов и детерминированно выбирает мастера по дневной загрузке. PostgreSQL exclusion constraint остаётся окончательной защитой от пересекающихся неотменённых записей.

Добавлены серверные сервисы создания записи, идемпотентного повтора, подтверждения и отмены по защищённой ссылке. Контракт и проверки описаны в [документации этапа 04.1](docs/booking-service.md), транзакции и токен — в [ADR-0003](docs/decisions/0003-booking-idempotency-and-protected-links.md).

Клиентский интерфейс 04.2 подключён к существующим сервисам: выбор услуги, мастера, даты и времени, контакты, подтверждение, безопасный повтор и отмена по fragment-ссылке. Добавлены Server Actions с проверкой Origin, PostgreSQL rate limits, no-store/no-referrer и nonce-CSP. Подробности, настройка доверенного proxy и ограничения хранения — в [документации 04.2](docs/public-booking.md). В 05.1 добавлены вход администратора, серверные сессии, защищённая стартовая страница и локальные команды создания/восстановления доступа. В 05.2 реализованы услуги, мастера, назначения, активность и порядок с защитой от устаревших форм. Исправление по результатам проверки связывает публичную запись с показанными условиями услуги и требует повторного согласия при их изменении; сохранённые попытки и ссылки совместимы. В 05.3 добавлено управление недельными часами, перерывами и исключениями через `/admin/schedule`; см. [настройку расписания](docs/admin-schedule.md). В 05.4 добавлены [настройки времени и горизонта](docs/admin-settings.md) с защитой старых форм и совместимым восстановлением попыток. В 05.5 добавлены [журнал, карточка и управление статусами](docs/admin-appointments.md), с историей, фильтрами, пагинацией и защитой от конкурирующих изменений. В 05.6 добавлено [ручное создание](docs/admin-appointment-creation.md): SPECIFIC/ANY, общий транзакционный engine, явное подтверждение, безопасный replay, готовый текст и fragment-ссылка. Редактирование и перенос существующей записи ещё не реализованы; Telegram остаётся этапом 06. Эксплуатация каталога — [admin-catalog.md](docs/admin-catalog.md). См. [инструкцию аутентификации](docs/admin-auth.md), [ADR-0005](docs/decisions/0005-admin-authentication-and-sessions.md) и Proposed [ADR-0011](docs/decisions/0011-admin-manual-appointment-creation.md).

## Локальный запуск

Требуются Node.js 24, npm и Docker с Compose. Скопируйте `.env.example` в `.env`, затем выполните:

```bash
npm install
docker compose up -d db
npm run prisma:migrate:deploy
npm run demo:seed # необязательно: только вымышленный каталог, без очистки данных
npm run dev
```

Приложение будет доступно на `http://localhost:3000`, health endpoint — на `http://localhost:3000/api/health`. PUBLIC_ORIGIN в .env должен точно совпадать с адресом браузера. Демокаталог не заполняется автоматически. Worker без Telegram-логики запускается командой `npm run worker`.

Для первого администратора после настройки DATABASE_URL и миграций выполните в интерактивном терминале `npm run admin:create`: пароль вводится скрыто и не передаётся в аргументах. Вход — `/admin/login`, выход — на `/admin`. Повторное создание не меняет существующего пользователя. Восстановление оператором — `npm run admin:reset` с отзывом всех сессий. Автоматических или демонстрационных учётных записей нет. Production требует HTTPS; HTTP разрешён только на loopback для локальной проверки.

Основные проверки:

```bash
npm run format:check
npm run lint
npm run build
npm run typecheck
npm run test:postgres
npm run test:e2e
docker compose config
```

Для полного Vitest-прогона без изменения существующей локальной БД используйте `node --env-file=.env.example scripts/test-postgres.mjs` (стандартный Docker Compose) либо `npm run test:postgres` с собственным `.env`. Команда создаёт отдельную временную БД, применяет миграции и удаляет только её после тестов; роли PostgreSQL нужно право `CREATE DATABASE`.
